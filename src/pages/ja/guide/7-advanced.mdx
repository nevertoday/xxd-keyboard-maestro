Keyboard Maestro をしばらく使っていると、これまでとは少し違う困りごとが出てきます。標準のアクションだけではできないけれど、ターミナルなら1行のコマンドで済むと分かっている作業がある。あるいはマクロが増えてきて、5つのマクロの最後がどれも同じ3つの手順になってしまい、1か所直すたびに5つ全部を直さなくてはならない。あるいは自宅と職場に1台ずつ Mac があって、片方で作ったマクロをもう片方でもう一度作り直す羽目になる、といった具合です。

<mark><strong>このステップで紹介する機能は、どれも必須ではありません。外の世界につながるいくつかの扉のようなもので、対応する困りごとに出会ったときに開ければ十分です。ほとんどの人は、このうち1つか2つしか使いません。</strong></mark>

そのため、このページは最初から最後まで通して読む必要はありません。どの項目も、最初に「それが何なのか」を説明し、最後に「どんなときに本当に必要になるか」を一文で書いています。その一文を読めば、今の自分に関係があるかどうかすぐ分かります。

## スクリプト：標準のアクションでは足りないとき

Keyboard Maestro では何種類かのスクリプトをそのまま実行できます。よく使うアクションは **Execute a Shell Script**（Shell スクリプトを実行）、**Execute an AppleScript**（AppleScript を実行）、**Execute a JavaScript For Automation**（JavaScript for Automation を実行、略して JXA）の3つです。スクリプトはアクションの中に直接書いても、別のファイルに置いて指定してもかまいません。実行結果の扱いも、無視する、ウィンドウに表示する、通知として表示する、今の入力欄に自動入力または貼り付ける、<Term k="变量" text="変数" />に保存する、クリップボードに入れる、あるいはスクリプトの完了を待たずにマクロをすぐ先へ進める、といったように選べます（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Scripting)）。

肝心なのは、スクリプトとマクロの間で変数をどう受け渡すかです。これは3種類のスクリプトそれぞれでやり方が違います。

### Shell スクリプト

Keyboard Maestro は、変数の名前の前に `KMVAR_` を付け、スペースをアンダースコアに置き換えた形で、スクリプトの環境変数に渡します（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Execute_a_Shell_Script#Using_Keyboard_Maestro_Variables)）。そのため、ステップ4の `Local Name` はスクリプトの中では `$KMVAR_Local_Name` になります。Local 変数や Instance 変数もこのアクションで使えます。初期設定ではすべての変数が渡されますが、スクリプトの横にあるメニューから「1つも渡さない」や「いくつかだけ渡す」に変更できます。

何も書き換えない小さな例を試してみましょう。アクションの結果は「ウィンドウに表示」に設定します。

<Copy id="s7-shell" title="Execute a Shell Script に書く内容" lang="sh" code={`echo "こんにちは、$KMVAR_Local_Name"\ndate`} />

ここでつまずきやすい点が2つあります。1つ目は、<u>これらの環境変数は読み取り専用で、スクリプトの中で書き換えても Keyboard Maestro 側の変数は変わらない</u>という点です。結果をマクロ側へ戻したいときは、スクリプトから結果を出力させ、アクション側の結果の扱いを「変数に保存」に設定します。2つ目は、このスクリプトが普段使っているターミナルの環境で動くわけではない点です。`.zshrc` のような設定ファイルは読み込まれず、コマンドを探す場所もシステムに最初から入っているいくつかのフォルダだけなので、自分で後から入れたコマンドは「見つからない」とエラーになることがあります。公式 Wiki では、コマンドのフルパスを書くか、`ENV_PATH` という名前の変数を作っておく方法が紹介されています。Keyboard Maestro はその値をスクリプトの `PATH` として使ってくれます（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Execute_a_Shell_Script#Path_in_Shell_Scripts)）。また、スクリプトの1行目に `#!` を使って、どの言語で動かすかを明記しておくことも勧められています。

### AppleScript

AppleScript でも環境変数から変数を読み取れますが、Keyboard Maestro Engine に直接やり取りを頼むこともできます。読み取りには `getvariable`、書き込みには `setvariable` を使うので、値をマクロ側へ書き戻すこともできます（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Execute_an_AppleScript#Using_Keyboard_Maestro_Variables)）。

```applescript
tell application "Keyboard Maestro Engine"
	set lastFolder to getvariable "Last Folder"
end tell
```

Local 変数や Instance 変数を読み書きする場合は、「どの実行回のものか」も指定する必要があります。環境変数 `KMINSTANCE` から今回の実行 ID を取り出し、`getvariable` に `instance` を書き加えます。具体的な書き方は、公式 Wiki の [Local & Instance Variables](https://wiki.keyboardmaestro.com/action/Execute_an_AppleScript#Local_Instance_Variables) の項目を見てください。

### JavaScript for Automation

Keyboard Maestro 11 以降、JXA スクリプトは初期設定で「Modern Syntax」が使われます。スクリプト全体が1つの関数で包まれる仕組みなので、結果は `return` でアクションに返します。変数は `kmvar` から取り出し、こちらも名前の中のスペースはアンダースコアに置き換えます（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Execute_a_JavaScript_For_Automation#Using_Keyboard_Maestro_Variables)）。Local 変数や Instance 変数は読み取れますが、パスワード変数は読み取れません。

```javascript
return "こんにちは、" + kmvar.Local_Name;
```

<strong>本当に必要になるのはこんなとき</strong>：やりたいことに合うアクションが Keyboard Maestro にないけれど、ターミナルのコマンドやアプリの AppleScript 機能を使えば実現できるとき。あるいは、もともと少しスクリプトを書けて、それをホットキーで呼び出したいときです。スクリプトを書かない人なら、ずっと触らないままでまったく問題ありません。

## サブルーチン：繰り返す手順は1回だけ書く

<Term k="子程序" text="サブルーチン" />とは、別のマクロから呼び出せるマクロのことです。公式 Wiki では「Web ページを PDF として保存する」処理が例に挙げられています。複数のマクロで同じ処理が必要になるとき、サブルーチンを1つだけ作っておけば、他のマクロはその場面でサブルーチンを呼び出し、URL と保存先を渡すだけで済みます（[公式 Wiki](https://wiki.keyboardmaestro.com/Subroutines)）。

設定は、呼ばれる側と呼ぶ側の両方で行います。

- <strong>呼び出される側のマクロ</strong>には、**Subroutine**（サブルーチン）トリガーを付けます。そこで、受け取るパラメータとそれぞれを入れる変数、そして結果を返すかどうかを設定します。結果を返すときは、マクロの中で **Return Result**（結果を返す）アクションを使います。
- <strong>呼び出す側のマクロ</strong>では、**Execute a Subroutine**（サブルーチンを実行）アクションを使います。呼び出したいマクロを選んで各パラメータの値を入れ、結果が返ってくる場合は受け取り先の変数を指定します（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Execute_a_Subroutine)）。

1つ落とし穴があります。<u>パラメータは名前ではなく順番で渡されます</u>。後から Subroutine トリガーのパラメータを増やしたり減らしたり、意味を変えたりすると、呼び出している側のマクロもすべて直す必要があります。トリガーにある **Callers**（呼び出し元）メニューを使えば、呼び出し元のマクロへすぐ移動できます。

パラメータも戻り値も不要で、ただ「別のマクロを実行したいだけ」なら、もっと手軽な **Execute a Macro**（マクロを実行）アクションで足ります。値を1つだけ渡すこともでき、呼ばれた側のマクロは `%TriggerValue%` トークンでそれを受け取ります。また、呼ばれた側のマクロからは今回の実行の Instance 変数も見えるので、ステップ4で触れた Instance と Local の違いがここで活きてきます。

<strong>本当に必要になるのはこんなとき</strong>：同じいくつかの手順がすでに3〜4個のマクロに出てきていて、1か所直すだけで何か所も書き換える羽目になったときです。マクロがまだ少ないうちは、急いで分ける必要はありません。

## 2台の Mac で同じマクロを使う

Keyboard Maestro のライセンスは1人あたり最大5台の Mac まで使えるため、複数台の Mac で同じマクロを使うのはよくあることです。方法は2つあります（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Macro_Syncing)）。

- <strong>いくつかのマクロだけ移す</strong>：移したいマクロを選び、**File ▸ Export ▸ Export Macros**（マクロを書き出す）でファイルに書き出して、もう1台の Mac で読み込みます。
- <strong>マクロ全体をずっと同期する</strong>：両方の Mac から見えて自動で同期されるフォルダが必要です。公式 Wiki では Dropbox のようなサービスや、常に接続できる共有ファイルサーバーが挙げられており、iCloud Drive は同期に時間がかかって変更が失われることがあると注意されています。マクロが入っている Mac で **File ▸ Start Syncing Macros**（マクロの同期を開始）を選び、表示される説明をよく読んだうえで **Create New**（新規作成）をクリックしてそのフォルダにマクロを保存します。ファイルが2台目の Mac に同期されたら、2台目でも **File ▸ Start Syncing Macros** を選び、**Open Existing**（既存のファイルを開く）をクリックしてそのファイルを指定します。

<Callout type="warn">
2台目の Mac で **Open Existing** をクリックすると、<u>その Mac にもともと入っていたマクロはすべて置き換わります</u>。残しておきたいマクロがある場合は、あらかじめ書き出しておき、同期を始めた後で読み込んでください。そうすれば、すべての Mac に同期されます。
</Callout>

同期を始めた後も、いくつか守っておきたいルールがあります。両方の Mac で Keyboard Maestro のバージョンをそろえること。同期されるのはマクロだけで、設定・クリップボード・変数は同期されないこと。両方の Mac で同時にマクロを編集しないこと（片方の変更が消えるおそれがあります）。あるマクログループだけ特定の Mac で動かしたくない場合は、その Mac でマクログループの **Disabled on this Mac**（この Mac ではオフ）をオンにします。詳しい手順は、ハウツーの「[2台の Mac で同じマクロを使う](/ja/howto/sync-macs/)」を見てください。

<strong>本当に必要になるのはこんなとき</strong>：2台以上の Mac で、本当に毎日同じマクロを使っているときです。たまにいくつか移すだけなら書き出しと読み込みで十分で、わざわざ同期を設定するほどではありません。

## マクロライブラリと共有

<Term k="宏库" text="マクロライブラリ" />は、Keyboard Maestro に最初から用意されている既製マクロの集まりです。**Window ▸ Macro Library**（マクロライブラリ）から開けます。それぞれのマクロに短い説明が付いていて、使えそうなものが見つかったら自分のマクロに追加してそのまま使ったり、ホットキーやアクションを少し変えて使ったりできます（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Macro_Library)）。Keyboard Maestro が最初から入れているマクロもすべてここに入っているので、Switcher Group からうっかり消してしまったマクロを戻したいときも、ここから取り出せます。

反対に、誰かに共有したくなる便利なマクロを作ったら、ファイルに書き出して送ることもできますし、エディタ画面の上部にある **Share**（共有）ボタンや **File ▸ Share**（共有）メニューを使うこともできます。詳しいやり方は、ハウツーの「[マクロを書き出す・読み込む・共有する](/ja/howto/share-macros/)」にまとめています。

<Callout type="no">
公式 Wiki でも注意されている通り、マクロは Mac 上でほとんど何でもできてしまうため、大きなトラブルを起こすことも可能です。<u>人からもらったマクロは、出どころを確認し、各手順が何をするのか理解できるまで実行しないでください。</u>
</Callout>

<strong>本当に必要になるのはこんなとき</strong>：使い始めたばかりで「みんな Keyboard Maestro でどんなことをしているんだろう」とヒントが欲しいときや、最初から入っていたマクロを元に戻したいときです。

## プラグインアクション

<Term k="插件动作" text="プラグインアクション" />は、他の人が作ったアクションです。Keyboard Maestro にインストールすると、標準のアクションと同じように使えます（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Plug_In_Actions)）。公式 Wiki では入手先として Keyboard Maestro の公式サイトと公式フォーラムが挙げられています。インストールするときは、<u>解凍しないで</u>、ダウンロードした `.zip` ファイルをそのまま Dock の Keyboard Maestro アイコンにドラッグします。追加したのに一覧に出てこない場合は、エンジンを終了してからエディタも終了し、もう一度エディタを開き直してください。追加されたアクションは、アクション一覧の **Third Party Plug Ins**（サードパーティプラグイン）というカテゴリに表示されます。

プラグインアクションも、人からもらったマクロと同じく自分の Mac 上で動くプログラムなので、信頼できる配布元のものだけをインストールしてください。

<strong>本当に必要になるのはこんなとき</strong>：やりたいことそのもののアクションをすでに誰かが作っていて、自分で長いアクションの並びを組み立てるよりずっと楽なときです。ほとんどの人は使う機会がありません。

## ブラウザや離れた場所からトリガーする

最後の2つは、この Mac の前に座っていないときでもマクロを実行できる仕組みです。

- **Web Server**（Web サーバー）：設定の **Web Server** タブでオンにすると、Web ブラウザからこの Mac の Keyboard Maestro にアクセスできるようになります。初期設定のアドレスは `http://localhost:4490` です。ユーザー名とパスワードを設定してログインすれば、アクティブになっているどのマクロも実行できます。**Public Web**（公開 Web）トリガーを付けたマクロは、この Mac に接続できる人なら誰でもパスワードなしで実行できます。公式 Wiki によると、一般的な家庭内ネットワークでは同じローカルネットワーク内のパソコンからしか接続できませんが、ネットワークの設定次第ではインターネット上の誰でも接続できてしまう可能性があります（[公式 Wiki](https://wiki.keyboardmaestro.com/trigger/Web_Server)）。
- **Remote**（リモート）トリガー：マクロに専用の URL が割り当てられ、Stairways Software の Web サーバーを経由して、インターネット上のどこからでもその URL を開くだけでログインなしにマクロを実行できます。公式 Wiki ははっきり警告しています。URL を知っている人なら誰でも動かせてしまうので、本当に無害なマクロにだけ使うこと。また、この機能が今後もずっと提供される保証も、毎回必ず動く保証もないので、大事な用途には頼らないでください（[公式 Wiki](https://wiki.keyboardmaestro.com/trigger/Remote)）。

<strong>本当に必要になるのはこんなとき</strong>：スマホや別のパソコンからちょっとタップするだけで、この Mac に差し支えのない小さな作業をさせたいときです。どちらの機能も、オンにする前に「誰がアクセスできる状態になるか」をよく考えてからにしてください。

これで完全ガイドは終わりです。ここからは順番に学ぶ必要はありません。具体的なやりたいことが出てきたら[ハウツー](/ja/howto/)で探し、知らない言葉に出会ったら [Wiki](/ja/wiki/) で調べてみてください。

## つまずいたときは

<Q q="ターミナルでは動く Shell スクリプトなのに、Keyboard Maestro で実行すると「コマンドが見つからない」と出ます。">
<p>Keyboard Maestro がスクリプトを実行するときは、システムに最初から入っているいくつかのフォルダからしかコマンドを探さず、ターミナルの設定も読み込みません。コマンドのフルパスを書くか、必要なパスを入れた <code>ENV_PATH</code> という名前の変数を作ってください。</p>
</Q>
<Q q="スクリプトの中から Keyboard Maestro の変数が読み取れません。">
<p>Shell スクリプトでは、<code>$KMVAR_</code> の後ろに、スペースをアンダースコアに置き換えた変数名を続けます。JXA では、<code>kmvar.</code> の後ろに同じくスペースをアンダースコアに置き換えた変数名を続けます。そのうえで、スクリプトの横にあるメニューが「変数を渡さない」設定になっていないか確認してください。なお、パスワード変数は JXA からはもともと読み取れません。</p>
</Q>
<Q q="Shell スクリプトの中で変数を書き換えたのに、マクロ側の値が変わりません。">
<p>環境変数は読み取り専用のコピーです。スクリプトから結果を出力させ、アクション側の結果の扱いを「変数に保存」に設定してください。AppleScript や JXA なら、<code>setvariable</code> を使って直接書き戻すこともできます。</p>
</Q>
<Q q="サブルーチンのパラメータを変更したら、それを呼び出しているマクロが動かなくなりました。">
<p>パラメータは順番で渡されます。サブルーチン側の Subroutine トリガーを開き、Callers メニューから呼び出し元のマクロへ1つずつ移動して、パラメータの並びを合わせ直してください。</p>
</Q>
<Q q="2台目の Mac で同期を始めたら、もともと入っていたマクロが消えてしまいました。">
<p>Open Existing をクリックすると、2台目の Mac のマクロは同期ファイルの中身に置き換わります。Keyboard Maestro は過去のバックアップを自動で残しているので、<strong>File ▸ Revert Macros</strong>（マクロを元に戻す）から必要な時点のものを探してみてください。次からは、先に書き出してから同期を始めるようにしてください。</p>
</Q>
<Q q="プラグインアクションをインストールしたのに、アクション一覧に見つかりません。">
<p>インストール後、認識されるまでにエディタとエンジンの両方を再起動する必要がある場合があります。まずエンジンを終了してから、エディタを終了して開き直し、Third Party Plug Ins のカテゴリを探してみてください。</p>
</Q>
