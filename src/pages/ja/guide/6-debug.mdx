ホットキーを押したのに何も起きない、あるいはマクロが途中まで動いて別のウィンドウに文字を打ってしまう——そんなときは、ついマクロを書き間違えたと思ってアクションを1つずつ見直しがちですが、30分かけて直してもやっぱり動かない、ということがよくあります。実はマクロ自体はどこも間違っていないことが多く、そもそもトリガーが反応していなかったり、macOS に操作を止められていたりするだけなのです。

<mark><strong>マクロが動かないときは、あわてて作り直さず、外側から順番に確認します。権限、エンジン、マクログループとマクロが有効かつアクティブか、トリガーがぶつかっていないか。そこまで問題ないとわかってから、はじめて中のアクションを1つずつ見ていきます。</strong></mark>

この順番は適当に決めたものではありません。外側の層に問題があると、すべてのマクロがまとめて動かなくなりますし、確認もすぐ終わります。内側へ入るほど、その1つのマクロだけの問題になり、原因を探すのにも手間がかかるからです。

## まずは Keyboard Maestro 自身に確認してもらう

エディタの **Help**（ヘルプ）メニューから **Interactive Help**（対話型ヘルプ）を選び、「Something expected is not happening」（起きるはずのことが起きない）をクリックします。すると、ほぼ同じ順番で自動的に調べてくれます。<Term k="引擎" text="エンジン" />が動いているか、エディタと通信できているか、Secure Input（セキュア入力）がオンになっていないか、アクセシビリティ権限が許可されているか、という流れです。そこまで問題なければ、動かないマクロをメニューから選ぶと、そのマクログループが有効かつアクティブか、マクロ自体が有効か、トリガーがあるか、有効なアクションが入っているかを調べてくれます。最後にトリガーを1回動かすと、どのマクロが反応したかがウィンドウに表示されます（[公式 Wiki](https://wiki.keyboardmaestro.com/Troubleshooting#Macros_Not_Firing_Triggered)）。

何も起きないのではなく「おかしな動きをする」場合は、代わりに「Something unexpected is happening」（意図しないことが起きている）を選びます。ここから先では、この診断が調べているそれぞれの層が実際には何なのか、そして自動診断で見つからないときに自分でどう確認すればよいかを説明します。

## 第1層：権限

公式 Wiki によると、開発元の Stairways Software に届くサポートメールの約80%は、Apple のセキュリティ権限に関するものだそうです。よくある原因は、アクセシビリティ、画面収録、あとで説明する Secure Input、そして App Translocation という仕組みです（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Troubleshooting)）。なかでも一番大切なのが<Term k="辅助功能权限" text="アクセシビリティ権限" />で、Keyboard Maestro が代わりにキーを押したり、ウィンドウを動かしたり、メニューを選んだりするのに欠かせません。

いちばん手っ取り早い確認方法は、メニューバーの **Keyboard Maestro ▸ Settings**（設定）から設定画面を開き、**Security**（セキュリティ）ペインを見ることです。大事な権限が一覧になっていて、オンになっているかどうかが一目でわかります。公式 Wiki でも、ここをすべてオンにするだけで多くの問題が解決するとしています。権限は **システム設定 ▸ プライバシーとセキュリティ ▸ アクセシビリティ** などの画面で許可します（古い macOS ではシステム環境設定）。初めて設定するときの手順は入門コースの[レッスン1](/ja/start/1-first-macro/)で紹介しています。エディタウィンドウの右下に黄色い警告の三角アイコンが出ている場合も、どこかの権限がオフになっているサインなので、クリックして案内に従います。

残念ながら、macOS の権限管理には Mojave 以降ずっと不具合が残っています。チェックボックスが表示されない、オンにできない、あるいはチェックが入っているのに実際には権限が効いていない、といったことが起きます。公式 Wiki では、次の方法をいくつか試すよう勧めています。

- Mac を再起動する。
- Keyboard Maestro と Keyboard Maestro Engine を一度終了して、起動し直す。
- Keyboard Maestro.app を <strong>Finder を使って</strong>「アプリケーション」フォルダへ移動したか確認する。ダウンロードした zip ファイルから直接開くと macOS の App Translocation が働き、Keyboard Maestro が正しく起動できなくなることがあります（[公式 Wiki](https://wiki.keyboardmaestro.com/Troubleshooting#Situation_1_--_New_Install)）。

もう1つ、権限の問題には見えないけれど実は権限絡みなのが Secure Input です。パスワード欄に入力している間、macOS はパスワードを盗み見られないように、どのアプリにもキーボード入力を見せない仕組みになっています。ところが、まれにシステムが「ずっとパスワード入力中」の状態で固まってしまい、ホットキーも<Term k="输入字符串触发器" text="入力文字列トリガー" />も一切反応しなくなることがあります。直前にパスワード入力を求めたアプリを終了するか、Mac を再起動すれば元に戻ります。Secure Input が固まっているのに Keyboard Maestro が気づいたときは、原因のプロセス名をステータスメニューや、エディタ右下の黄色い三角アイコンの中に表示してくれます（[公式 Wiki](https://wiki.keyboardmaestro.com/Troubleshooting#Secure_Input_Mode)）。

## 第2層：エンジンは動いているか

実際にマクロを実行しているのは、裏側で動いている Keyboard Maestro Engine であって、マクロを作るためのエディタウィンドウではありません。エディタは閉じても構いませんが、エンジンは動いている必要があります。メニューバーに Keyboard Maestro のアイコンがあるか見てみましょう。アイコンが出ていればエンジンは動いています。なければ、Keyboard Maestro を一度開くだけでエンジンも起動します。毎回ログインしたときに自動で立ち上がるように、設定画面の **General**（一般）で **Launch Engine at Login**（ログイン時にエンジンを起動）をオンにしておきます（[公式 Wiki](https://wiki.keyboardmaestro.com/Troubleshooting#Macros_Not_Firing_After_You_Login)）。

## 第3層：マクログループとマクロは有効かつアクティブか

マクロが動くには、2つの条件を両方満たしている必要があります。マクロとその<Term k="宏组" text="マクログループ" />がどちらも有効になっていて、さらにマクログループが今まさにアクティブな状態であることです（[公式 Wiki](https://wiki.keyboardmaestro.com/Macro_Activation)）。

有効かどうかは、マクロとマクログループの右上にある ✔ や ✖ でわかります。クリックすれば切り替えられますし、**View ▸ Toggle Enable**（有効・無効の切り替え）でも変更できます。アクティブかどうかはマクログループの設定次第です。たとえば Safari でだけ動く設定のグループなら、メールを使っているときにホットキーを押しても当然何も起きませんし、先にアクティブにする必要があるグループは、アクティブにするまで動きません。こうした設定は[ステップ1](/ja/guide/1-groups/)で説明しています。確認するときは、キーを押したときにどのアプリが一番手前にあったかを気にしてみてください。

## 第4層：トリガーがぶつかっていないか

アクティブな2つのマクロに同じホットキーや同じ入力文字列が設定されていると、Keyboard Maestro はどちらを実行したいのか判断できません。そのため、候補を並べた小さな Conflict Palette（競合パレット）を表示します。クリックして選ぶか、1つに絞られるまで文字を打って実行します（[公式 Wiki](https://wiki.keyboardmaestro.com/Conflict_Palette)）。つまり、ホットキーを押したときに小さな一覧が出てきても故障ではなく、トリガーが重なっているだけです。どちらかのホットキーを変えるか、別々のアプリでアクティブになるマクログループに分ければ解消します。逆に、関連するマクロにわざと同じホットキーを割り当ててパレットから選ぶようにすれば、覚える組み合わせを減らすこともできます。

衝突は Keyboard Maestro の外側でも起きます。ホットキーを押すと Keyboard Maestro がそのキーを受け取るため、アプリ自身のメニューにある同じショートカットは効かなくなります。また、別のアプリも同じホットキーをシステム全体に登録している場合は、マクロと別アプリの機能の両方が同時に動きます（[公式 Wiki](https://wiki.keyboardmaestro.com/trigger/Hot_Key#Terminology)）。⌃⌥⌘（Control-Option-Command）に文字を1つ足すような組み合わせにしておけば、ほかの機能とぶつかることはめったにありません。

## 第5層：動きはするけれど、思った通りに動かない

ここまできたら、マクロ自体は確かに動いています。ただ、思った通りの動き方になっていません。いちばん多い原因はアクションの書き間違いではなく「速すぎること」です。アプリ側の準備が整う前にマクロが次の処理へ進んでしまうため、手順を飛ばしたように見えたり、途中で止まったりします。公式 Wiki が勧める対処法は、マクロを待たせることです。手軽なのは **Pause**（一時停止）アクションを入れる方法で、公式 Wiki によれば0.3秒ほどで十分なことが多いそうです。さらに確実なのは、ある条件がそろうまで待つ **Pause Until**（条件を満たすまで待機）で、使い方は[ステップ4](/ja/guide/4-variables/)で解説しています（[公式 Wiki](https://wiki.keyboardmaestro.com/Troubleshooting#Timing_Between_Actions)）。

どこでつまずいているのか見当がつかないときは、マクロに1つずつ進んでもらって自分の目で確かめます。

### デバッガ：1つずつ進めて確認する

<Term k="调试器" text="デバッガ" />は、マクロの動きをゆっくりにして1アクションごとに止め、中身を目で追いかけられるウィンドウです（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Macro_Debugger)）。

1. メニューバーの Keyboard Maestro のアイコンをクリックし、**Start Debugging**（デバッグを開始）を選びます。**Macro Debugger**（マクロデバッガ）ウィンドウが開きます。
2. ウィンドウ内の **Pause New Macros**（新しいマクロを一時停止）にチェックが入っていることを確認します。
3. いつも通りにマクロをトリガーします。マクロがウィンドウに現れ、先頭で一時停止します。
4. 下向き矢印のボタンをクリックして最初のアクションに進み、その後もクリックするたびに1つずつ先へ進めます。

左側のボタンのうち、**Continue**（続行）は最後まで一気に実行し、**Step Over**（まとめて次へ）は現在のアクションを、その中に入っているアクションも含めてまとめて実行します。**Step In To**（中へ入る）はアクションの中に入り、**Step Out Of**（外へ出る）は今の階層を最後まで進めて抜けます。右側の **Edit**（編集）は現在のアクションをエディタで開き、**Cancel**（キャンセル）はそのマクロを中止します。右上のボタンを押すと、この実行で直近に変わった10個の変数が表示されるので、値が合っているか一目で確かめられます。

知っておきたいことが2つあります。1つ目は、マクロが動き始めるとエンジンはそのコピーを実行するため、実行中にエディタで書き換えても今動いている回には反映されないことです。2つ目は、<u>デバッガで1つずつ進めるとうまくいくのに普通に動かすと失敗する場合、ほぼ間違いなく速すぎるのが原因</u>だということです。1回ずつクリックしている間はアプリ側が追いつく余裕があるからです。失敗する手順の直前に Pause を入れてみてください。なお、デバッガウィンドウを閉じると、一時停止していたマクロは通常通り再開されます。

### Log アクションとエンジンログ

デバッガに表示される変数は10個までです。もっと見たいときは、マクロに **Log**（ログ記録）アクションを追加します。書いたテキストを Engine.log というファイルに書き出してくれて、その中にトークンや変数も混ぜられます。たとえば「ここまで到達、名前は `%Variable%Local Name%`」のように書けます（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Log)）。画面ですぐ確認したいときは、**Display Text**（テキストを表示）を使えばウィンドウに表示できます。

<Term k="引擎日志" text="エンジンログ" />には、自分で書き出した内容だけでなく、アクションが失敗したときの原因も記録されます。エディタで **Help ▸ Open Logs Folder**（ログフォルダを開く）を選び、Engine.log を開いて末尾の数行を読んでみてください。自分のマクロの記録があれば、少なくともトリガーは反応しています。1行も残っていなければ、前の層へ戻って確認します（[公式 Wiki](https://wiki.keyboardmaestro.com/Troubleshooting#Situation_6_--_After_New_Macros_or_Actions)）。あわせて、Keyboard Maestro Engine の通知が許可されているかも確認しておきましょう。アクションが失敗すると通知で教えてくれるため、オフになっていると見逃してしまいます。

よく知らないアクションがあれば、その右上の歯車メニューから **Help** を選びます。公式 Wiki にあるそのアクションの解説ページが開きます。

## 止まらないマクロを止める

マクロが同じところを回り続けたり、文字を打ち続けたりしても、あわてる必要はありません。止める方法はいくつもあります（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/How_do_I)）。

- <strong>1つだけ止める</strong>：メニューバーの Keyboard Maestro のアイコンをクリックし、**Cancel** の中からそのマクロを選びます。今どのマクロが動いているかも、この一覧で確認できます。
- <strong>すべて止める</strong>：⌃⌥⇧（Control-Option-Shift、⌘ を一緒に押しても押さなくても構いません）を押しながらメニューバーの Keyboard Maestro のアイコンをクリックすると、実行中のマクロがすべて中止されます。
- <strong>デバッガから止める</strong>：**Start Debugging** のウィンドウには実行中のマクロがすべて並んでいるので、**Cancel** をクリックします。
- <strong>緊急停止ボタンを作る</strong>：**Cancel All Macros**（すべてのマクロをキャンセル）や **Cancel This Macro**（このマクロをキャンセル）といったアクションもマクロに入れられます。ホットキーを付けておけば、自分専用の緊急停止ボタンになります。

それでも止まらなければ、ステータスメニューから Keyboard Maestro Engine を終了します。ログイン時に動くマクロのせいでメニューすら触れない場合でも、⌃⌥⇧⌘ を押し続けながらエディタを開くなど、より徹底した方法が公式 Wiki に載っています。こうするとエンジンが終了して再起動もしなくなるので、落ち着いてそのマクロを直せます。詳しくはハウツーの[マクロが止まらなくなったとき](/ja/howto/stop-macro/)を見てください。

## それでも解決しないときは、どこで質問するか

公式 Wiki によると、具体的なマクロの作り方や不具合については、[公式フォーラム](https://forum.keyboardmaestro.com/)で聞くのがいちばん早いそうです。親切に答えてくれる人がたくさんいます。投稿するときは、使っている macOS と Keyboard Maestro のバージョン、本来どう動かしたいか、実際には何が起きているかを書き、できれば書き出したマクロも添付しましょう（[公式 Wiki](https://wiki.keyboardmaestro.com/Troubleshooting#Situation_3_--_After_Update_to_New_Version_of_Keyboard_Maestro)）。投稿する前に、ライセンス情報やパスワード、個人的な文章が入っていないか確認して消しておきます。

これで、マクロが思うように動かないときにどこから調べればよいかがわかりました。最後のステップは必須ではありませんが、Keyboard Maestro をもう一歩深く使うための扉として、スクリプト、サブルーチン、同期、共有を紹介します。

## つまずいたときは

<Q q="ホットキーを押したのに、何も起きません。">
<p>順番に確認します。メニューバーに Keyboard Maestro のアイコンがあるか（エンジンが動いているか）、設定の Security で権限がすべてオンになっているか、マクロとマクログループの両方に ✔ が付いているか、キーを押したとき最前面にあったアプリでそのグループがアクティブになる設定か、の順です。迷ったら、Help メニューの Interactive Help に診断してもらってください。</p>
</Q>
<Q q="ホットキーを押すと、小さな一覧が出てきます。">
<p>それは Conflict Palette（競合パレット）で、アクティブな2つ以上のマクロに同じホットキーが設定されているときに出ます。動かしたいものをクリックすればそのまま実行できます。毎回選びたくなければ、どちらかのホットキーを変えておきます。</p>
</Q>
<Q q="急にホットキーも入力文字列も一切効かなくなりました。">
<p>ほとんどの場合、Secure Input が固まっているか、エンジンが終了しています。まずメニューバーに Keyboard Maestro のアイコンがあるか確認し、直前にパスワード入力を求めたアプリを終了してみてください。それでも直らなければ Mac を再起動します。Secure Input が固まっているのを Keyboard Maestro が検知すると、ステータスメニューに原因のプロセス名が表示されます。</p>
</Q>
<Q q="システム設定で権限にチェックを入れたのに、Keyboard Maestro には権限がないと言われます。">
<p>macOS の権限管理に昔からある不具合です。Mac を再起動し、Keyboard Maestro とエンジンを一度終了して起動し直してください。また、Keyboard Maestro.app が Finder を使って「アプリケーション」フォルダへ移動されているかも確認しましょう。</p>
</Q>
<Q q="デバッガで1つずつ進めると動くのに、普通に動かすと失敗します。">
<p>アプリの反応よりマクロが速すぎます。失敗する手順の直前に Pause を入れるか、Pause Until を使ってそのウィンドウが現れるまで待つようにします。</p>
</Q>
<Q q="マクロを書き換えたのに、まだ前の動きのままです。">
<p>すでに実行中の回は開始時のコピーで動いているため、変更は次回から反映されます。ステータスメニューの Cancel で一度止めてから、もう一度トリガーしてみてください。</p>
</Q>
