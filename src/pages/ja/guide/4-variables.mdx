こんなマクロを作ったことはないでしょうか。キーを1回押すだけで取引先への定番の返信を入力してくれるので、ずいぶん手間が省けます。ただ、冒頭の「〇〇さん、こんにちは」は毎回手で書き直していますし、忙しい週には2文目もまるごと差し替えています。マクロは決められた通りにしか動かないため、使いながら結局あとから手で直すことになってしまいます。

<mark><strong>このステップで学ぶのは、マクロが動く前にまず状況を確かめる仕組みです。テキストを覚えておき、ひとこと尋ね、答えに合わせて道を変え、何かが起きるまで待ってから次へ進めるようになります。</strong></mark>

ここまでに作ってきたマクロは、「いつ動かすか」と「決まった一連のアクション」の組み合わせでした（[ステップ0](/ja/guide/0-what/)、[ステップ3](/ja/guide/3-actions/)）。このステップでは、そこにいくつかの要素を加えます。<Term k="变量" text="変数" />、<Term k="令牌" text="トークン" />、<Term k="计算" text="計算式" />、そして<Term k="条件" text="条件" />です。プログラミングのように聞こえますが、どれもマクロにドラッグして欄を埋めるだけの、ただのアクションです。

## 先に尋ねてくれる返信マクロ

まずは完成後の動きを見てみましょう。ホットキーを押すと小さなウィンドウが開き、相手の名前と、今週空きがあるかどうかの2つを尋ねてきます。名前を入力し、メニューから「予定いっぱい」を選んで Return キーを押すと、マクロがこう入力してくれます。

> Alexさん、ご連絡ありがとうございます。今週は予定がいっぱいのため、来週の月曜日に詳しい内容をお返事します。

「空きあり」を選ぶと、後半が「今週の金曜日までにお返事します。」に変わります。マクロ全体はアクション2つだけです。

1. **Prompt for User Input**（ユーザー入力を求める）：ウィンドウのタイトルを「返信」にして、変数の行を2つ追加します。1行目は変数名を `Local Name` にして、初期値は空のままにします。2行目は変数名を `Local Week` にして、初期値に `空きあり|予定いっぱい` と入力します。縦棒で区切って初期値を書くとポップアップメニューになり、先頭の項目が最初から選ばれた状態になります（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Prompt_for_User_Input)）。
2. **If Then Else**（もし〜なら／そうでなければ）：条件欄の緑色のプラスをクリックして **Variable Condition**（変数の条件）を選び、`Local Week` **is**（一致する）`予定いっぱい` と設定します。上半分に **Insert Text by Pasting**（テキストを貼り付けて挿入）を置いて下の1つ目の文章を入れ、下半分にも同じアクションを置いて2つ目の文章を入れます。

<Copy id="s4-busy" title="上半分：予定がいっぱいの週" code="%Variable%Local Name%さん、ご連絡ありがとうございます。今週は予定がいっぱいのため、来週の月曜日に詳しい内容をお返事します。" />

<Copy id="s4-free" title="下半分：空きがある週" code="%Variable%Local Name%さん、ご連絡ありがとうございます。今週の金曜日までにお返事します。" />

このマクロを1つ作るだけで、このステップで扱う要素のほとんどに触れられます。ここからは1つずつ詳しく見ていきましょう。

## 変数：テキストに名前を付けておく

変数は、名前の付いた箱のようなものです。前のアクションがテキストを入れておくと、あとのアクションがその名前で中身を取り出せます。あらかじめ宣言しておく必要はなく、最初に値を保存したアクションがその場で自動的に作ってくれます。名前は英字で始め、そのあとは英字・数字・スペース・アンダースコアが使えます。大文字と小文字は区別されないため、`Local Name` と `local name` は同じ変数として扱われます（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Variables#Variable_Naming_Rules)）。

値を保存するいちばん直接的な方法は **Set Variable to Text**（変数にテキストを設定）アクションです。先ほどの例で使わなかったのは、**Prompt for User Input** 自体が入力された内容をそのまま変数に保存してくれるためです。

### 変数に入るのはテキストだけ

公式 Wiki にもはっきり書かれていますが、変数に入るのはプレーンテキストだけです。フォントや色などの書式は付かず、画像も入れられません。数字でさえテキストとして保存されます。`3` はあくまで「3」という1文字にすぎず、数値を入力する欄に入れたときに初めて、Keyboard Maestro が数として扱います。書式付きのテキストや画像をあとで使うために残しておきたいときは、次のステップで学ぶ<Term k="命名剪贴板" text="名前付きクリップボード" />を使います。

### Global、Local、Instance：いつまで残るか、どこから見えるか

変数の名前が何で始まるかによって、その変数がいつまで残るか、どのマクロから見えるかが決まります（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Variables#Scope)）。

<Fig id="4-variables-scope" />

- Global（グローバル）変数：特別な接頭辞を付けない名前です。すべてのマクロから読み書きでき、スクリプトからも読めます。Mac に保存されるので再起動しても消えません。Keyboard Maestro の設定にある **Variables**（変数）ペインで一覧を見たり書き換えたりできます。
- Instance（インスタンス）変数：`Instance` で始まる名前です。その1回の実行だけに属し、そのマクロ本体と、その実行中に呼び出したサブマクロから見えます。実行が終わると消えます。同じマクロが同時に2回動いても、それぞれ別のコピーを持ちます。
- Local（ローカル）変数：`Local` で始まる名前です。こちらもその1回の実行だけに属しますが、見えるのはそのマクロ本体だけで、呼び出したサブマクロからは見えません。

このほか、名前の先頭か末尾に `PW` または `Password` が付くパスワード変数もあります。メモリ上だけに置かれ、ディスクには一切書き込まれません。実際に必要になったときに公式 Wiki で確認すれば十分です。

では、ふだんはどれを使えばいいのでしょうか。公式 Wiki のおすすめは、<u>その1回の実行中にしか使わないものは、Local か Instance を優先すること</u>です。同じマクロが同時に複数動くことがあり、Global 変数を共有しているとお互いの値を上書きしてしまいます。それに Global 変数はいつまでも残るため、以前に保存したパスワードや長いテキストまで含めて、設定画面に古い値がどんどん溜まっていきます。先の例で `Local Name` にしたのもそのためで、相手の名前はその返信の1回だけに必要で、終わったら消えてほしいからです。前回選んだフォルダなど、次回まで本当に覚えておかせたいときだけ Global 変数を使います。

## トークンと計算式：文字の中に変数を、数字の欄に数式を

変数の中身を文章の中に埋め込むときに使うのが<Term k="令牌" text="トークン" />です。トークンはパーセント記号で挟んだ名前で、アクションが実行されるときに実際の内容に置き換わります。たとえば `%LongDate%` は今日の日付に変わります（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Tokens)）。変数を呼び出すトークンは `%Variable%変数名%` なので、先の例では `%Variable%Local Name%` と書きました。名前を丸暗記する必要はありません。テキスト欄にカーソルを置いて **Edit ▸ Insert Token**（編集 ▸ トークンを挿入）メニューから選ぶか、入力欄の右上にある Insert Token ポップアップから選べます（中身は同じ一覧です）。

数値を入力する欄は仕組みが違います。こうした欄には数式をそのまま書くことができ、これを<Term k="计算" text="計算式" />と呼びます。たとえば **Pause**（一時停止）の秒数に `60*Local Minutes` と書けば、「分数 × 60」秒だけ待機します（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Calculations)）。<u>計算欄ではパーセント記号を付けず、変数名をそのまま書きます</u>。`%Variable%Local Minutes%` と書くと計算できません。また、変数の中身は数値か数式になっている必要があります。公式 Wiki にある例でいうと、変数に `2*3` というテキストが入っていれば、`4*` に続けてその変数を書いた式は 24 になります。計算結果を変数に保存したいときは、**Set Variable to Calculation**（変数に計算結果を設定）を使います。

今編集している欄がどの種類なのかは、編集時に欄の中に表示される小さなアルファベットで見分けられます。**T** はトークンを使えるテキスト欄、**C** は数式を書ける計算欄、**V** は変数名だけを1つ入れる欄です（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Variables#Using_Variables)）。

## Prompt for User Input：先にひとこと尋ねる

**Prompt for User Input** は小さな入力フォームを表示して、答えた項目をそれぞれ変数に保存します。各行の初期値の書き方で入力欄の種類が決まり、普通のテキストなら入力ボックス、`|` で区切った項目ならポップアップメニュー、パスワード変数なら入力した文字が黒丸で隠れるパスワード欄になります。初期値の右側にあるメニューからは、チェックボックス・スライダー・カラー・日付と時刻など、ほかの種類も選べます。

フォーム上では名前の `Local` の部分が自動で隠れるため、`Local Name` はただの「Name」と表示されます。ここでも遠慮なく Local 変数を使って大丈夫です。

フォームには最初から2つのボタンが付いています。**OK** は Return キーに対応し、押すとウィンドウが閉じてマクロが先へ進みます。**Cancel**（キャンセル）は Esc キーまたは ⌘.（Command＋ピリオド）に対応し、<u>Cancel を押すと入力した内容は一切保存されず、マクロ全体がそこで止まります</u>。これはあえてそういう仕様になっていて、気が変わったのにマクロがそのまま入力を続けてしまわないようにするためです。「下書き保存」などの独自ボタンを追加することもでき、どれが押されたかはあとから `%PromptButton%` トークンで確認できます（[公式 Wiki](https://wiki.keyboardmaestro.com/token/PromptButton)）。

もっと詳しい手順は、ハウツーの[作業の前に質問する](/ja/howto/ask-input/)を見てみてください。

## If Then Else と Switch/Case：状況に応じて道を変える

**If Then Else** には条件を並べておきます。条件を満たせば上半分のアクションを、満たさなければ下半分のアクションを実行します。条件欄の緑色のプラスをクリックして追加し、カテゴリから選びます。特定のアプリが起動しているか・最前面にあるか、変数の中身は何か、クリップボードにテキストが入っているか、画面上に特定の画像があるかなど、選べる条件はたくさんあります。公式 Wiki に[条件の一覧](https://wiki.keyboardmaestro.com/Conditions)がまとまっています。

条件が2つ以上あるときは、一番上の行で組み合わせ方を選びます（[公式 Wiki](https://wiki.keyboardmaestro.com/manual/Conditions)）。

- **any of the following are true**：少なくとも1つが成り立つとき。
- **all of the following are true**：すべてが成り立つとき。
- **none of the following are true**：1つも成り立たないとき。
- **not all of the following are true**：少なくとも1つは成り立たないとき。

1つ落とし穴があります。<u>条件を1つも追加していないと、If Then Else は上も下もどちらも実行しません</u>。マクロがまとまった処理をまるごと飛ばしているように見えるときは、条件を入れ忘れていないか確認してみてください。

分岐が3通り以上になると、If Then Else の中にさらに If Then Else を入れ子にしていくのはあっという間に読みにくくなります。そんなときは **Switch/Case**（値ごとに分岐する）に切り替えます。まず何を見るか（クリップボード、変数、テキスト、計算式）を選び、あとは値ごとに1つずつセクションを追加します（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Switch_or_Case)）。たとえば返信マクロのメニューを `空きあり|予定いっぱい|休暇中` に変えたなら、`Local Week` を見る Switch に3つのセクションを作り、それぞれの文章を入れます。Switch は最初に一致したセクションだけを実行し、そのまま次のセクションへ流れ込むことはありません。最後のセクションは **otherwise**（それ以外）にでき、上のどれにも当てはまらなかったときに実行されるため、いちばん下に置きます。

## Pause Until：何かが起きるまで待つ

マクロはアプリより速く動きます。テキストエディットを開いてすぐ文字を打つように組むと、ウィンドウがまだ出ていないうちに別の場所へ入力されてしまいます。決まった秒数だけ待つ方法でも一応しのげますが、Mac が混み合っているときは足りず、空いているときは無駄に待つことになります。そこで **Pause Until**（条件を満たすまで待機）を使うと、時間ではなく条件を待てるようになります。**Application Condition**（アプリの条件）を追加してテキストエディットが **is at the front**（最前面にある）と設定しておけば、テキストエディットが最前面に出た瞬間にマクロが先へ進みます（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Pause_Until)）。

使う条件や any／all の組み合わせ方は、If Then Else と同じです。待ち時間が長くなると、CPU の負担を減らすために確認する間隔が少しずつ長くなります。10秒を過ぎると少し控えめに、60秒を過ぎるとぐっと控えめになります。この動きを止めたい場合は、アクションの歯車メニューからオフにできます。[入門コースのレッスン3](/ja/start/3-one-key-routine/)で作ったような、アプリをいくつか開いてからウィンドウを並べるマクロこそ、Pause Until がいちばん活躍する場面です。

## 3つのループ：同じ一連のアクションを何度も繰り返す

同じ一連のアクションを何回も動かしたいときは、いくつもコピーして並べるのではなく、ループで囲みます。

- **Repeat**（指定回数繰り返す）：決まった回数だけ実行します。回数の欄は計算欄なので、直前に尋ねて入力してもらった回数など、変数をそのまま入れられます（[公式 Wiki](https://wiki.keyboardmaestro.com/action/Repeat)）。
- **For Each**（1つずつ処理する）：まとまった対象を1つずつ順番に処理します。変数名と「集まり」（テキストの各行、Finder で選択中のファイル、連番など）を指定すると、1周ごとに1つずつ変数へ入れて中のアクションを実行します（[公式 Wiki](https://wiki.keyboardmaestro.com/action/For_Each)）。手元に「処理したいリスト」があるときは、まずこれを使います。
- **While Conditions Are Met**（条件を満たすあいだ繰り返す）：開始時に条件を確認し、成り立つときだけ中に入ります。条件が成り立たなくなった時点で、すぐ止まります（[公式 Wiki](https://wiki.keyboardmaestro.com/action/While)）。

どのループでも、**Break From Loop**（ループを抜ける）を使えば途中で抜けられます。また、Repeat と For Each は歯車メニューから進捗表示をオンにできるので、長いループを回すときに便利です。

<Callout type="warn">
条件がいつまでも成り立ち続ける While や、待っていることが一向に起きない Pause Until は、マクロを動かし続けてしまいます。まずは止め方を覚えておきましょう。メニューバーにある Keyboard Maestro のアイコンをクリックし、**Cancel** の中からそのマクロを選びます。ほかの止め方は[ステップ6](/ja/guide/6-debug/)で紹介しています。
</Callout>

これでマクロは、覚える・尋ねる・判断する・待つ・繰り返すことができるようになりました。次はクリップボードです。変数には入らない書式付きのテキストや画像を、どこに置いて扱うかを見ていきます。

## つまずいたときは

<Q q="入力された文章で、名前の部分だけが空欄になります。">
<p>まず、トークンに書いた変数名と値を保存したときの変数名が、スペースも含めて一字一句一致しているか確認します。そのうえで、別のマクロやサブマクロから Local 変数を読もうとしていないかも見てみてください。Local 変数はそのマクロ本体からしか見えません。サブマクロに渡すなら Instance、次回まで残すなら Global を使います。</p>
</Q>
<Q q="計算欄でエラーが出るか、結果が 0 になります。">
<p>計算欄では <code>%Variable%</code> を付けず、変数名をそのまま書きます。あわせて、変数の中身が本当に数値になっているかも確認してください。「三」や「3個」のような文字が入っていては計算できません。</p>
</Q>
<Q q="If Then Else の上も下もどちらも実行されません。">
<p>ほとんどの場合、条件が1つも追加されていません。公式 Wiki にも、条件がないとどちらも実行されないと明記されています。</p>
</Q>
<Q q="Prompt for User Input で Cancel を押すと、マクロ全体が止まってしまいます。">
<p>それが本来の動きです。Cancel は何も保存せず、マクロ自体をキャンセルします。別のルートに進むだけのボタンを作りたい場合は、新しいボタンを追加して、あとから <code>%PromptButton%</code> で押されたボタンを確認します。</p>
</Q>
<Q q="OK を押したのに、元のウィンドウに返信が入力されません。">
<p>小さなウィンドウが閉じたあと、キーボードのフォーカスが元のアプリへ戻る前にマクロが貼り付けてしまうと、テキストが行き場を失います。公式 Wiki でも、ウィンドウを開閉したりフォーカスを移したりするアクションの直後は少し待つ必要がある場合が多いと説明されています。<strong>Prompt for User Input</strong> と <strong>If Then Else</strong> のあいだに <strong>Pause</strong> を入れてみてください。だいたい0.3秒ほどあれば十分です（<a href="https://wiki.keyboardmaestro.com/Frequently_Asked_Questions#When_do_I_need_a_Pause">公式 Wiki</a>）。</p>
</Q>
<Q q="Pause Until がずっと待ち続けて、マクロが先に進みません。">
<p>待っている条件がいつまでも成り立っていません。まずステータスメニューの Cancel からそのマクロを止め、条件を確認します。選んだアプリは合っているか、「最前面にある」にしたいのか「起動している」だけでいいのかを見直してみてください。</p>
</Q>
<Q q="設定の Variables ペインに、変数がずらっと溜まっています。">
<p>そこに並んでいるのは Global 変数で、マクロが終わっても自動では消えません。その1回の実行でしか使わないものは、Local で始まる名前に変えておきます。もう不要な変数は、値を空にすれば残らなくなります。</p>
</Q>
