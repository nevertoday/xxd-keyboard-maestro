혹시 이런 매크로 하나쯤 있지 않나요? 키 하나만 누르면 고객에게 자주 보내는 답장을 쭉 입력해 줘서 타자 칠 일을 크게 줄여 주는 매크로 말이에요. 그런데 첫머리의 “안녕하세요, 아무개 님”은 매번 손으로 고쳐야 하고, 바쁜 주에는 두 번째 문장도 통째로 바꿔 써야 해요. 매크로가 적어 둔 대로만 움직이다 보니, 결국 쓰면서 뒷수습을 하게 되죠.

<mark><strong>이번 단계에서는 매크로가 움직이기 전에 먼저 상황을 파악하도록 만드는 법을 배워요. 텍스트를 기억하고, 먼저 한마디 물어보고, 대답에 따라 다른 길로 가고, 어떤 일이 일어날 때까지 기다렸다가 다음으로 넘어가는 거예요.</strong></mark>

지금까지 만든 매크로는 “언제 실행할지”에 “정해진 동작 목록”을 붙인 형태였어요([0단계](/ko/guide/0-what/), [3단계](/ko/guide/3-actions/)). 이번 단계에서는 그 목록에 <Term k="变量" text="변수" />, <Term k="令牌" text="토큰" />, <Term k="计算" text="계산식" />, <Term k="条件" text="조건" />을 더해 볼 거예요. 프로그래밍처럼 들리지만, 하나하나 따져 보면 그저 매크로에 끌어다 놓고 칸 몇 개만 채우면 되는 동작일 뿐이에요.

## 먼저 물어보는 답장 매크로

완성하면 이런 모습이 돼요. 단축키를 누르면 작은 창이 뜨면서 두 가지를 물어봐요. 상대방 이름이 무엇인지, 그리고 이번 주에 여유가 있는지예요. 이름을 적고 메뉴에서 “일정 가득”을 고른 뒤 Return 키를 누르면, 매크로가 이렇게 입력해요.

> 안녕하세요, Alex 님. 연락 주셔서 감사합니다. 이번 주는 일정이 가득 차서, 다음 주 월요일에 자세한 내용을 다시 안내해 드릴게요.

“여유 있음”을 고르면 뒷부분이 “이번 주 금요일까지 답변드릴게요.”로 바뀌어요. 전체 매크로는 동작 두 개면 끝이에요.

1. **Prompt for User Input**(사용자 입력 요청): 창 제목을 “답장”으로 적고 변수 줄을 두 개 추가하세요. 첫 번째 변수 이름은 `Local Name`으로 하고 기본값은 비워 둬요. 두 번째 변수 이름은 `Local Week`로 하고 기본값에 `여유 있음|일정 가득`을 넣으세요. 세로 막대로 항목을 구분한 기본값은 팝업 메뉴로 바뀌고, 첫 번째 항목이 기본으로 선택돼요([공식 위키](https://wiki.keyboardmaestro.com/action/Prompt_for_User_Input)).
2. **If Then Else**(조건 분기): 조건 영역의 초록색 더하기 버튼을 클릭해 **Variable Condition**(변수 조건)을 고르고, `Local Week` **is**(일치) `일정 가득`으로 설정하세요. 위쪽 칸에는 **Insert Text by Pasting**(붙여넣기로 텍스트 삽입) 동작을 넣어 아래 첫 번째 문구를 채우고, 아래쪽 칸에도 같은 동작을 하나 더 넣어 두 번째 문구를 채워요.

이 매크로 하나만 만들어 봐도 이번 단계에서 다룰 내용은 거의 다 맛본 셈이에요. 이제 구성 요소를 하나씩 살펴볼게요.

## 변수: 텍스트에 이름 붙이기

변수는 이름표가 붙은 상자예요. 앞선 동작이 그 안에 텍스트를 넣어 두면, 뒤이은 동작이 이름으로 꺼내 쓰는 식이죠. 미리 선언할 필요는 없어요. 처음으로 값을 저장하는 동작이 알아서 변수를 만들어 주거든요. 변수 이름은 영문자로 시작해야 하고, 그 뒤에는 영문자, 숫자, 공백, 밑줄을 넣을 수 있어요. 대소문자는 구분하지 않아서 `Local Name`과 `local name`은 같은 변수예요([공식 위키](https://wiki.keyboardmaestro.com/manual/Variables#Variable_Naming_Rules)).

변수에 값을 넣는 가장 직접적인 방법은 **Set Variable to Text**(변수에 텍스트 설정) 동작이에요. 앞의 예시에서 이 동작을 쓰지 않은 이유는, **Prompt for User Input**이 입력한 내용을 알아서 변수에 저장해 주기 때문이에요.

### 변수에는 텍스트만 들어가요

공식 위키에서도 아주 단호하게 말해요. 변수에는 일반 텍스트만 들어가고, 서체나 색상은 담기지 않으며 이미지도 넣을 수 없어요. 심지어 숫자도 텍스트로 저장돼요. `3`은 그저 “3”이라는 글자일 뿐이고, 숫자를 받는 입력 칸에 넣었을 때 비로소 Keyboard Maestro가 숫자로 계산해 줘요. 서식이 있는 글이나 이미지를 두고두고 보관하려면 다음 단계에서 배울 <Term k="命名剪贴板" text="이름 지정 클립보드" />를 써야 해요.

### Global, Local, Instance: 얼마나 오래 남고, 누가 볼 수 있는지

변수 이름이 무엇으로 시작하느냐에 따라 그 변수가 얼마나 오래 유지되는지, 어떤 매크로에서 볼 수 있는지가 달라져요([공식 위키](https://wiki.keyboardmaestro.com/manual/Variables#Scope)).

<Fig id="4-variables-scope" />

- Global(전역) 변수는 이름 앞에 특별한 접두사가 없어요. 모든 매크로가 읽고 바꿀 수 있고 스크립트에서도 읽을 수 있으며, Mac에 저장되어 재시동한 뒤에도 남아 있어요. Keyboard Maestro 설정의 **Variables**(변수) 탭에서 확인하고 수정할 수 있어요.
- Instance 변수는 `Instance`로 시작해요. 딱 이번 한 번의 실행에만 속해서, 이 매크로와 실행 중에 호출한 하위 매크로만 볼 수 있고 실행이 끝나면 사라져요. 같은 매크로가 동시에 두 번 돌아가도 각각 자기 몫을 따로 가져요.
- Local 변수는 `Local`로 시작해요. 역시 이번 한 번의 실행에만 속하지만, 오직 이 매크로 자신만 볼 수 있고 호출한 하위 매크로에서는 볼 수 없어요.

이름이 `PW`나 `Password`로 시작하거나 끝나는 비밀번호 변수도 있어요. 메모리에만 머물고 디스크에는 저장되지 않아요. 실제로 필요할 때 공식 위키 페이지를 참고해 보세요.

그렇다면 평소에는 어떤 걸 쓰면 좋을까요? 공식 위키에서는 <u>한 번 실행할 때만 필요한 값이라면 Local이나 Instance를 우선해서 쓰라</u>고 권해요. 같은 매크로가 동시에 여러 번 실행될 수 있는데, 이때 Global 변수를 함께 쓰면 서로의 값을 덮어써 버리거든요. 게다가 Global 변수는 계속 쌓이기 때문에, 예전에 저장해 둔 비밀번호나 긴 텍스트까지 설정에 그대로 남게 돼요. 앞의 예시에서 `Local Name`을 쓴 이유도 바로 이거예요. 이 이름은 이번 답장에만 필요하고, 쓰고 나면 사라져야 하니까요. 마지막으로 고른 폴더처럼 다음번 실행 때까지 꼭 기억해 둬야 하는 값에만 Global 변수를 쓰세요.

## 토큰과 계산식: 텍스트에는 변수를, 숫자 칸에는 수식을

텍스트 안에 변수의 값을 넣을 때는 <Term k="令牌" text="토큰" />을 써요. 토큰은 퍼센트 기호 사이에 넣은 이름으로, 동작이 실행될 때 실제 내용으로 바뀌어요. 예를 들어 `%LongDate%`는 오늘 날짜로 바뀌죠([공식 위키](https://wiki.keyboardmaestro.com/manual/Tokens)). 변수에 해당하는 토큰은 `%Variable%변수명%`이에요. 그래서 앞의 예시에서 `%Variable%Local Name%`이라고 쓴 거예요. 이름을 다 외울 필요는 없어요. 텍스트 입력 칸에 커서를 두고 **Edit ▸ Insert Token**(편집 ▸ 토큰 삽입) 메뉴를 쓰거나, 입력 칸 오른쪽 위에 있는 Insert Token 팝업 메뉴에서 고르면 똑같은 목록이 나와요.

숫자를 받는 칸은 방식이 달라요. 여기에는 수식을 바로 적을 수 있는데, 이를 <Term k="计算" text="계산식" />이라고 해요. 예를 들어 **Pause**(일시 정지)의 시간 칸에 `60*Local Minutes`라고 적으면 “분 값에 60을 곱한 초”만큼 멈춰요([공식 위키](https://wiki.keyboardmaestro.com/manual/Calculations)). <u>계산식 칸에서는 퍼센트 기호 없이 변수 이름만 그대로 적어야 해요.</u> `%Variable%Local Minutes%`처럼 쓰면 계산되지 않아요. 변수 안에 들어 있는 텍스트도 숫자나 수식이어야 해요. 공식 위키의 예시를 들면, 변수에 `2*3`이라는 텍스트가 들어 있을 때 `4*` 뒤에 그 변수를 붙여 계산하면 결과는 24가 돼요. 계산 결과를 변수에 저장하려면 **Set Variable to Calculation**(변수에 계산식 설정)을 쓰세요.

지금 편집하는 칸이 어떤 종류인지 어떻게 알 수 있을까요? 입력 칸을 편집할 때 나타나는 작은 알파벳을 보면 돼요. **T**는 토큰을 넣을 수 있는 텍스트 칸, **C**는 계산식 칸, **V**는 변수 이름만 넣는 칸이에요([공식 위키](https://wiki.keyboardmaestro.com/manual/Variables#Using_Variables)).

## Prompt for User Input: 먼저 물어보기

**Prompt for User Input**은 작은 입력 창을 띄워 두고, 입력한 답을 각각 변수에 저장해요. 각 줄의 기본값을 어떻게 적느냐에 따라 입력 칸 모양이 달라져요. 일반 텍스트를 적으면 입력 상자가 되고, `|`로 항목을 나누면 팝업 메뉴가 되며, 비밀번호 변수를 쓰면 입력할 때 점으로 표시되는 비밀번호 칸이 돼요. 기본값 오른쪽의 메뉴에서는 체크박스, 슬라이더, 색상, 날짜와 시간 같은 다른 형식도 직접 고를 수 있어요.

입력 창에는 변수 이름의 `Local` 부분이 숨겨져서 `Local Name`이 그냥 “Name”으로만 표시돼요. 그러니 여기서는 마음 편히 Local 변수를 쓰세요.

입력 창에는 버튼이 기본으로 두 개 들어가요. **OK**(확인)은 Return 키에 연결되어 있어서, 누르면 창이 닫히고 매크로가 계속 진행돼요. **Cancel**(취소)는 Esc 키나 ⌘.(Command-마침표)에 연결되어 있고, <u>Cancel을 누르면 아무 값도 저장하지 않고 매크로 전체가 그대로 멈춰요.</u> 일부러 그렇게 만들어 둔 거예요. 마음을 바꿨는데 매크로가 계속 글을 입력하면 안 되니까요. “임시 저장”처럼 원하는 버튼을 따로 추가한 뒤, 뒤에서 `%PromptButton%` 토큰으로 어느 버튼을 눌렀는지 확인할 수도 있어요([공식 위키](https://wiki.keyboardmaestro.com/token/PromptButton)).

더 자세한 과정은 활용법의 [작업하기 전에 먼저 물어보기](/ko/howto/ask-input/)를 참고하세요.

## If Then Else와 Switch/Case: 상황에 따라 다른 길로 가기

**If Then Else**에는 조건 묶음이 들어가요. 조건이 맞으면 위쪽 칸의 동작을 실행하고, 맞지 않으면 아래쪽 칸을 실행하죠. 조건 영역의 초록색 더하기 버튼을 클릭해 조건을 추가하고 종류를 고를 수 있어요. 어떤 앱이 실행 중인지나 맨 앞에 있는지, 변수에 어떤 값이 들어 있는지, 클립보드에 텍스트가 있는지, 화면에 특정 이미지가 있는지 등 고를 수 있는 조건이 아주 많아요. 공식 위키에 [전체 조건 목록](https://wiki.keyboardmaestro.com/Conditions)이 정리되어 있어요.

조건이 두 개 이상이면 맨 윗줄에서 조건을 어떻게 조합할지 고를 수 있어요([공식 위키](https://wiki.keyboardmaestro.com/manual/Conditions)).

- **any of the following are true**: 하나라도 맞으면 성립해요.
- **all of the following are true**: 모두 맞아야 성립해요.
- **none of the following are true**: 하나도 맞지 않아야 성립해요.
- **not all of the following are true**: 적어도 하나는 맞지 않아야 성립해요.

주의할 함정이 하나 있어요. <u>조건을 하나도 넣지 않으면 If Then Else는 위쪽도 아래쪽도 실행하지 않아요.</u> 매크로가 한 구역을 통째로 건너뛰는 것처럼 보일 때는, 조건 추가를 깜빡하지 않았는지 먼저 확인해 보세요.

경우가 세 가지 이상으로 늘어나면 If Then Else 안에 또 If Then Else를 겹쳐 넣게 되어 금세 보기 어려워져요. 그럴 때는 **Switch/Case**(값에 따라 분기)로 바꿔 쓰면 돼요. 먼저 무엇을 기준으로 볼지(클립보드, 변수, 텍스트, 계산식) 고른 다음, 값마다 구역을 하나씩 추가하세요([공식 위키](https://wiki.keyboardmaestro.com/action/Switch_or_Case)). 예를 들어 답장 매크로의 메뉴를 `여유 있음|일정 가득|휴가 중`으로 바꾸고 `Local Week`를 기준으로 Switch를 만들면, 문장 하나씩 들어가는 세 구역이 생겨요. Switch는 처음 일치한 구역 하나만 실행하고 다음 구역으로 이어서 실행하지 않아요. 마지막 구역은 **otherwise**(그 외의 경우)로 둘 수 있는데, 위에서 일치한 항목이 하나도 없을 때 실행되므로 반드시 맨 아래에 두어야 해요.

## Pause Until: 어떤 일이 일어날 때까지 기다리기

매크로는 앱보다 빨라요. 텍스트 편집기를 열고 바로 글을 입력하라고 시키면, 창이 아직 뜨기도 전에 글자가 엉뚱한 곳에 들어가 버려요. 정해진 시간만큼 멈추게 하는 것도 얼추 통하긴 하지만, Mac이 바쁠 때는 시간이 모자라고 한가할 때는 괜히 시간만 버리게 돼요. **Pause Until**(조건 충족까지 일시 정지)는 시계 대신 조건을 기다려요. **Application Condition**(앱 조건)을 추가해 텍스트 편집기를 고르고 **is at the front**(맨 앞에 있음)으로 설정하면, 텍스트 편집기가 맨 앞에 올라오는 순간 매크로가 바로 이어서 움직여요([공식 위키](https://wiki.keyboardmaestro.com/action/Pause_Until)).

이 동작도 If Then Else와 똑같은 조건과 조합 방식을 써요. 기다리는 시간이 길어지면 CPU 부담을 줄이려고 확인 간격을 점점 늘려요. 10초가 지나면 조금 덜 확인하고, 60초가 지나면 훨씬 덜 확인하죠. 원하지 않으면 동작의 톱니바퀴 메뉴에서 끌 수 있어요. [입문 레슨 3](/ko/start/3-one-key-routine/)에서 만든 것처럼 앱 몇 개를 연 뒤 창을 배치하는 매크로에서 Pause Until이 특히 제 몫을 톡톡히 해내요.

## 세 가지 반복: 같은 동작을 여러 번 하기

같은 동작을 여러 번 해야 할 때는 여러 개 복사해서 붙여넣지 말고 반복 동작으로 감싸세요.

- **Repeat**(반복)은 정해진 횟수만큼 동작을 실행해요. 횟수 칸은 계산식 칸이라서, 방금 입력받은 숫자 같은 변수를 넣을 수도 있어요([공식 위키](https://wiki.keyboardmaestro.com/action/Repeat)).
- **For Each**(하나씩 반복)은 여러 항목을 하나씩 차례대로 처리해요. 변수 이름과 대상 목록(예를 들어 텍스트의 각 줄, Finder에서 선택한 파일들, 숫자 범위 등)을 지정하면, 한 바퀴 돌 때마다 항목 하나를 변수에 넣고 안쪽 동작을 실행해요([공식 위키](https://wiki.keyboardmaestro.com/action/For_Each)). 처리해야 할 “목록”이 있을 때 가장 먼저 떠올려 보세요.
- **While Conditions Are Met**(조건이 맞는 동안 반복)은 시작할 때 먼저 조건을 확인해서 맞을 때만 안으로 들어가요. 그러다 조건이 맞지 않게 되는 순간 바로 멈춰요([공식 위키](https://wiki.keyboardmaestro.com/action/While)).

세 가지 반복 모두 안에서 **Break From Loop**(반복 중단)을 쓰면 중간에 빠져나올 수 있어요. Repeat와 For Each는 톱니바퀴 메뉴에서 진행 표시를 켤 수도 있어서, 오래 도는 반복 작업을 지켜볼 때 편리해요.

<Callout type="warn">
조건이 끝까지 참으로 남는 While이나, 기다리는 일이 영영 일어나지 않는 Pause Until을 쓰면 매크로가 멈추지 않고 계속 돌아가요. 멈추는 법부터 익혀 두세요. 메뉴 막대의 Keyboard Maestro 아이콘을 클릭하고 **Cancel** 아래에서 해당 매크로를 고르면 돼요. 더 다양한 중지 방법은 [6단계](/ko/guide/6-debug/)에서 다뤄요.
</Callout>

이제 매크로가 기억하고, 묻고, 판단하고, 기다리고, 반복하는 일까지 다 할 수 있게 됐어요. 다음 단계는 클립보드예요. 변수에 담지 못하는 서식 있는 글과 이미지를 어디에 두는지 알아볼게요.

## 막혔나요?

<Q q="입력된 글에서 이름 자리가 비어 있어요.">
<p>먼저 토큰에 적은 변수 이름과 값을 저장할 때 쓴 변수 이름이 공백까지 한 글자도 틀리지 않고 같은지 확인해 보세요. 그다음에는 Local 변수를 다른 매크로나 하위 매크로에서 읽으려 한 건 아닌지 살펴보세요. Local 변수는 오직 그 매크로 자신만 볼 수 있어요. 하위 매크로와 나누어 쓰려면 Instance를, 다음 실행 때까지 남겨 두려면 Global을 쓰세요.</p>
</Q>
<Q q="계산식 칸에 오류가 뜨거나 결과가 0으로 나와요.">
<p>계산식 칸에서는 <code>%Variable%</code> 없이 변수 이름만 그대로 적어야 해요. 그다음 변수 안에 정말로 숫자가 들어 있는지도 확인하세요. “셋”이나 “3개” 같은 텍스트는 계산되지 않아요.</p>
</Q>
<Q q="If Then Else의 위쪽도 아래쪽도 실행되지 않아요.">
<p>대부분 조건을 하나도 넣지 않아서 그래요. 공식 위키에도 조건이 없으면 양쪽 다 실행되지 않는다고 나와 있어요.</p>
</Q>
<Q q="Prompt for User Input에서 Cancel을 눌렀더니 매크로 전체가 멈췄어요.">
<p>원래 그렇게 동작해요. Cancel은 아무 값도 저장하지 않고 매크로 전체를 취소하거든요. 누르면 다른 길로만 가게 하고 싶은 버튼이라면 새 버튼을 하나 추가하고, 뒤에서 <code>%PromptButton%</code>으로 어느 버튼이 눌렸는지 확인하세요.</p>
</Q>
<Q q="OK를 눌렀는데 답장이 원래 있던 창에 입력되지 않았어요.">
<p>작은 입력 창이 닫히고 나면 키보드 초점이 원래 쓰던 앱으로 돌아가야 하는데, 그보다 먼저 매크로가 붙여넣기를 해 버리면 글자가 허공으로 사라져요. 공식 위키에서도 창을 열거나 닫고 초점이 옮겨 가는 동작 뒤에는 잠깐 기다려야 하는 경우가 많다고 해요. <strong>Prompt for User Input</strong>과 <strong>If Then Else</strong> 사이에 <strong>Pause</strong>를 하나 넣어 보세요. 보통 0.3초 정도면 충분해요(<a href="https://wiki.keyboardmaestro.com/Frequently_Asked_Questions#When_do_I_need_a_Pause">공식 위키</a>).</p>
</Q>
<Q q="Pause Until이 계속 기다리기만 하고 매크로가 넘어가지 않아요.">
<p>기다리는 조건이 끝내 성립하지 않은 거예요. 먼저 상태 메뉴의 Cancel에서 이 매크로를 멈춘 뒤 조건을 확인해 보세요. 앱을 맞게 골랐는지, “맨 앞에 있음”이 필요했던 건지 아니면 단순히 “실행 중”이면 되는 건지 살펴보세요.</p>
</Q>
<Q q="설정의 Variables 탭에 변수가 잔뜩 쌓여 있어요.">
<p>그건 모두 Global 변수라서, 매크로가 끝나도 저절로 사라지지 않아요. 한 번 실행할 때만 쓰는 변수는 Local로 시작하는 이름으로 바꿔 주세요. 이미 필요 없어진 변수는 값을 비워 두면 더 이상 남지 않아요.</p>
</Q>
