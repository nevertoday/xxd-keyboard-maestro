Keyboard Maestro를 한동안 쓰다 보면 전과는 다른 종류의 고민이 생겨요. 기본 동작으로는 못 하는 일인데 터미널 명령어 한 줄이면 해결될 걸 알 때가 있어요. 아니면 매크로가 점점 늘어나서 다섯 개나 되는 매크로가 똑같은 세 단계로 끝나는데, 한 곳을 고치려면 다섯 군데를 다 바꿔야 할 수도 있죠. 집에 Mac 한 대, 회사에 Mac 한 대가 있어서 한쪽에서 만든 매크로를 다른 쪽에서 또 만들어야 할 때도 있고요.

<mark><strong>이 단계의 내용은 어느 것도 필수가 아니에요. 각각 바깥으로 이어지는 문 같은 기능이라서, 딱 맞는 문제가 생겼을 때 열어 보면 돼요. 대부분은 이 중에서 한두 개만 쓰게 돼요.</strong></mark>

그래서 이 페이지는 처음부터 끝까지 다 읽을 필요가 없어요. 각 절은 그 기능이 무엇인지로 시작해서, 실제로 언제 필요한지 알려 주는 한 문장으로 끝나요. 그 문장만 읽어 봐도 이 절이 나에게 필요한 내용인지 바로 알 수 있어요.

## 스크립트: 기본 동작만으로 부족할 때

Keyboard Maestro는 여러 종류의 스크립트를 직접 실행할 수 있어요. 가장 자주 쓰는 동작 세 가지는 **Execute a Shell Script**(셸 스크립트 실행), **Execute an AppleScript**(AppleScript 실행), **Execute a JavaScript For Automation**(JavaScript for Automation 실행, 줄여서 JXA)예요. 스크립트는 동작 안에 직접 입력해도 되고, 따로 저장해 둔 파일을 지정해도 돼요. 실행 결과를 어떻게 처리할지도 고를 수 있어요. 무시하거나, 창에 띄우거나, 알림으로 보여 주거나, 현재 텍스트 입력 칸에 타이핑하거나 붙여넣거나, <Term k="变量" text="변수" />에 저장하거나, 클립보드에 넣을 수 있고, 스크립트가 끝나길 기다리지 않고 매크로를 바로 다음 단계로 넘길 수도 있어요([공식 위키](https://wiki.keyboardmaestro.com/manual/Scripting)).

여기서 중요한 건 변수를 어떻게 넣고 빼는지인데, 스크립트 종류마다 방법이 달라요.

### 셸 스크립트

Keyboard Maestro는 매크로의 변수를 스크립트의 환경 변수로 넣어 줘요. 이때 변수 이름 앞에 `KMVAR_`를 붙이고, 이름 속 공백은 밑줄로 바꿔요([공식 위키](https://wiki.keyboardmaestro.com/action/Execute_a_Shell_Script#Using_Keyboard_Maestro_Variables)). 그래서 4단계에서 만든 `Local Name`은 스크립트 안에서 `$KMVAR_Local_Name`이 돼요. Local 변수와 Instance 변수도 이 동작에서 읽을 수 있어요. 기본 설정에서는 모든 변수가 다 넘어가지만, 스크립트 옆 메뉴에서 아무 변수도 넘기지 않거나 몇 개만 골라 넘기도록 바꿀 수 있어요.

아무것도 바꾸지 않는 간단한 예시예요. 결과는 창에 표시하도록 설정해 보세요.

<Copy id="s7-shell" title="Execute a Shell Script에 입력할 내용" lang="sh" code={`echo "안녕하세요, $KMVAR_Local_Name"\ndate`} />

여기서 두 가지 때문에 자주 막혀요. 첫째, <u>이 환경 변수는 읽기 전용이라 스크립트 안에서 값을 바꿔도 Keyboard Maestro 변수는 바뀌지 않아요</u>. 결과를 되돌려받으려면 스크립트가 그 값을 출력하게 만들고, 동작의 결과를 변수에 저장하도록 설정하세요. 둘째, 스크립트는 평소 쓰던 터미널 환경에서 실행되지 않아요. `.zshrc` 같은 설정 파일을 읽지 않고, 시스템에 기본으로 들어 있는 몇몇 폴더에서만 명령어를 찾아요. 그래서 직접 설치한 명령어는 “찾을 수 없음” 오류가 날 수 있어요. 공식 위키에서는 명령어의 전체 경로를 적어 주거나, `ENV_PATH`라는 변수를 만들어 두는 방법을 안내해요. Keyboard Maestro는 이 변수를 스크립트의 `PATH`로 사용하거든요([공식 위키](https://wiki.keyboardmaestro.com/action/Execute_a_Shell_Script#Path_in_Shell_Scripts)). 또 스크립트 첫 줄에 `#!` 줄을 넣어 어떤 언어를 쓰는지 밝혀 두라고 권장해요.

### AppleScript

AppleScript도 환경 변수에서 값을 읽을 수 있지만, Keyboard Maestro Engine에 직접 물어볼 수도 있어요. 읽을 때는 `getvariable`, 쓸 때는 `setvariable`을 써요. 값을 매크로 쪽으로 돌려보낼 때 쓰는 게 바로 `setvariable`이에요([공식 위키](https://wiki.keyboardmaestro.com/action/Execute_an_AppleScript#Using_Keyboard_Maestro_Variables)).

```applescript
tell application "Keyboard Maestro Engine"
	set lastFolder to getvariable "Last Folder"
end tell
```

Local 변수나 Instance 변수를 다루려면 어느 실행의 변수인지도 알려 줘야 해요. `KMINSTANCE` 환경 변수에서 이번 실행의 ID를 읽어 온 뒤, `getvariable` 뒤에 `instance`를 덧붙이면 돼요. 자세한 작성법은 공식 위키의 [Local & Instance Variables](https://wiki.keyboardmaestro.com/action/Execute_an_AppleScript#Local_Instance_Variables) 절에 나와 있어요.

### JavaScript for Automation

Keyboard Maestro 11부터 JXA 스크립트는 기본적으로 “Modern Syntax”를 써요. 스크립트 전체가 함수 하나로 감싸져 있기 때문에 결과는 `return`으로 돌려줘요. 변수는 `kmvar`에서 가져오며, 여기서도 이름의 공백은 밑줄로 바뀌어요([공식 위키](https://wiki.keyboardmaestro.com/action/Execute_a_JavaScript_For_Automation#Using_Keyboard_Maestro_Variables)). Local 변수와 Instance 변수는 읽을 수 있지만, 비밀번호 변수는 읽을 수 없어요.

```javascript
return "안녕하세요, " + kmvar.Local_Name;
```

<strong>실제로 필요할 때</strong>: 원하는 작업에 맞는 동작이 Keyboard Maestro에는 없는데 터미널 명령어나 특정 앱의 AppleScript 기능으로는 해결할 수 있을 때, 또는 이미 간단한 스크립트를 짤 줄 알아서 단축키에 연결해 쓰고 싶을 때예요. 스크립트를 쓰지 않는다면 평생 건드리지 않아도 전혀 괜찮아요.

## 서브루틴: 반복되는 단계를 한 번만 쓰기

<Term k="子程序" text="서브루틴" />은 다른 매크로가 불러다 쓸 수 있는 매크로예요. 공식 위키에서는 웹 페이지를 PDF로 저장하는 일을 예로 들어요. 여러 매크로에서 이 작업이 필요하다면 서브루틴을 하나만 만들어 두고, 나머지 매크로는 그 단계에서 서브루틴을 호출해 URL과 저장할 위치만 넘겨주면 돼요([공식 위키](https://wiki.keyboardmaestro.com/Subroutines)).

설정은 양쪽에서 나눠서 해요.

- <strong>호출되는 매크로</strong>에는 **Subroutine**(서브루틴) 트리거를 추가해요. 여기에서 받을 매개변수 목록, 각 값을 저장할 변수, 결과를 돌려줄지 여부를 정해 둬요. 결과를 돌려주려면 매크로 안에서 **Return Result**(결과 반환) 동작을 쓰면 돼요.
- <strong>호출하는 매크로</strong>에서는 **Execute a Subroutine**(서브루틴 실행) 동작을 써요. 호출할 매크로를 고르고 각 매개변수에 값을 채워 넣은 뒤, 돌려받을 결과가 있다면 그걸 담을 변수 이름을 지정해 주세요([공식 위키](https://wiki.keyboardmaestro.com/action/Execute_a_Subroutine)).

주의할 함정이 하나 있어요. <u>매개변수는 이름이 아니라 순서대로 전달돼요</u>. 나중에 **Subroutine** 트리거에서 매개변수를 추가하거나 지우거나 의미를 바꾸면, 그 서브루틴을 호출하는 매크로도 모두 함께 고쳐야 해요. 트리거의 **Callers**(호출한 매크로) 메뉴를 열면 호출하는 매크로들로 바로 이동할 수 있어요.

매개변수나 반환 결과가 필요 없고 그저 다른 매크로를 한 번 실행하고 싶을 뿐이라면, 더 간단한 **Execute a Macro**(매크로 실행) 동작으로 충분해요. 이 동작으로도 값 하나는 넘길 수 있고, 호출된 매크로는 `%TriggerValue%` 토큰으로 그 값을 읽어요. 또 호출된 매크로는 이번 실행의 Instance 변수도 함께 볼 수 있어요. 4단계에서 배운 Instance 변수와 Local 변수의 차이가 바로 여기서 쓰여요.

<strong>실제로 필요할 때</strong>: 똑같은 몇 단계가 이미 서너 개의 매크로에 들어가 있어서, 한 번 고칠 때마다 여러 군데를 수정해야 하는 상황이 왔을 때예요. 매크로가 아직 몇 개 없다면 서둘러 나눌 필요 없어요.

## 두 대의 Mac에서 같은 매크로 쓰기

Keyboard Maestro 라이선스 하나는 한 사람이 최대 다섯 대의 Mac까지 쓸 수 있어서, 여러 Mac에서 같은 매크로를 쓰는 일이 흔해요. 방법은 두 가지예요([공식 위키](https://wiki.keyboardmaestro.com/manual/Macro_Syncing)).

- <strong>매크로 몇 개만 옮기기</strong>: 옮길 매크로를 선택한 뒤 **File ▸ Export ▸ Export Macros**(파일 ▸ 내보내기 ▸ 매크로 내보내기)로 내보내고, 다른 Mac에서 그 파일을 가져오면 돼요.
- <strong>전체 매크로를 계속 동기화하기</strong>: 두 Mac이 모두 접근할 수 있고 자동으로 동기화되는 폴더가 필요해요. 공식 위키에서는 Dropbox 같은 서비스나 항상 열려 있는 공유 파일 서버를 예로 들면서, iCloud Drive는 동기화가 오래 걸려 변경 내용이 사라질 수 있으니 주의하라고 해요. 매크로가 들어 있는 Mac에서 **File ▸ Start Syncing Macros**(파일 ▸ 매크로 동기화 시작)을 선택하고, 안내 문구를 꼼꼼히 읽은 다음 **Create New**(새로 만들기)를 클릭해 그 폴더에 매크로를 저장하세요. 파일이 두 번째 Mac으로 동기화되면, 그 Mac에서도 똑같이 **File ▸ Start Syncing Macros**를 선택하고 **Open Existing**(기존 파일 열기)를 클릭해 그 파일을 고르면 돼요.

<Callout type="warn">
두 번째 Mac에서 **Open Existing**을 클릭하면 <u>그 Mac에 원래 있던 매크로가 모두 덮어씌워져요</u>. 남겨 두고 싶은 매크로가 있다면 먼저 내보내기 해 둔 뒤, 동기화를 켠 다음에 다시 가져오세요. 그러면 모든 Mac으로 함께 동기화돼요.
</Callout>

동기화를 켠 뒤에는 몇 가지 규칙을 지켜야 해요. 두 Mac의 Keyboard Maestro 버전이 같아야 해요. 그리고 매크로만 동기화될 뿐, 설정이나 클립보드, 변수는 동기화되지 않아요. 두 Mac에서 동시에 매크로를 수정하면 한쪽의 변경 내용이 사라질 수 있으니 피하세요. 특정 매크로 그룹이 어느 한 Mac에서만 실행되지 않게 하려면, 그 Mac에서 해당 그룹의 **Disabled on this Mac**(이 Mac에서 사용 안 함) 설정을 켜 두면 돼요. 단계별 전체 과정은 활용법의 [Mac 두 대에서 같은 매크로 쓰기](/ko/howto/sync-macs/)를 참고하세요.

<strong>실제로 필요할 때</strong>: 정말로 두 대 이상의 Mac에서 매일 같은 매크로를 쓸 때예요. 가끔 매크로 몇 개만 옮기는 정도라면 내보내기·가져오기로 충분하고, 굳이 동기화까지 설정할 필요는 없어요.

## 매크로 라이브러리와 공유

<Term k="宏库" text="매크로 라이브러리" />는 Keyboard Maestro에 기본으로 딸려 오는 완성된 매크로 모음이에요. **Window ▸ Macro Library**(윈도우 ▸ 매크로 라이브러리)에서 열 수 있어요. 매크로마다 짧은 설명이 붙어 있어서 쓸 만해 보이는 걸 내 매크로에 넣은 뒤 그대로 쓰거나, 단축키나 동작만 입맛에 맞게 고쳐 쓰면 돼요([공식 위키](https://wiki.keyboardmaestro.com/manual/Macro_Library)). Keyboard Maestro를 설치할 때 기본으로 들어 있는 매크로도 모두 여기 들어 있어요. 그래서 Switcher Group에서 매크로를 하나 지웠다가 다시 쓰고 싶어졌을 때도 여기에서 되찾을 수 있어요.

반대로 다른 사람과 나누고 싶은 매크로를 만들었다면 파일로 내보내 전달하거나, 편집기 창 위쪽의 **Share**(공유) 버튼이나 **File ▸ Share**(파일 ▸ 공유) 메뉴를 쓰면 돼요. 자세한 방법은 활용법의 [매크로 내보내기, 가져오기, 공유하기](/ko/howto/share-macros/)에서 다뤄요.

<Callout type="no">
공식 위키는 매크로가 Mac에서 사실상 무엇이든 할 수 있고, 큰 피해를 줄 수도 있다고 경고해요. <u>다른 사람이 준 매크로는 어디서 온 건지 확인하고 각 단계가 무슨 일을 하는지 이해하기 전에는 실행하지 마세요.</u>
</Callout>

<strong>실제로 필요할 때</strong>: 처음 시작하면서 다른 사람들은 Keyboard Maestro로 뭘 하는지 아이디어를 얻고 싶을 때, 또는 기본 매크로 중 하나를 되찾고 싶을 때예요.

## 플러그인 동작

<Term k="插件动作" text="플러그인 동작" />은 다른 사람이 만들어 둔 동작을 Keyboard Maestro에 설치해 기본 동작처럼 쓰는 기능이에요([공식 위키](https://wiki.keyboardmaestro.com/manual/Plug_In_Actions)). 공식 위키에서는 Keyboard Maestro 웹사이트와 공식 포럼에서 이런 플러그인을 구할 수 있다고 안내해요. 설치할 때는 <u>압축을 풀지 말고</u>, 내려받은 `.zip` 파일을 그대로 Dock의 Keyboard Maestro 아이콘 위로 끌어다 놓으세요. 설치한 뒤에도 보이지 않으면 엔진을 종료하고, 편집기도 닫았다가 다시 열어 보세요. 동작 목록의 **Third Party Plug Ins**(외부 플러그인) 분류에 나타나요.

플러그인 동작도 다른 사람이 준 매크로와 마찬가지로 내 Mac에서 실행되는 코드예요. 그러니 믿을 수 있는 출처에서 받은 것만 설치하세요.

<strong>실제로 필요할 때</strong>: 내가 하려는 일에 딱 맞는 동작을 다른 사람이 이미 만들어 두어서, 직접 긴 동작을 이어 붙이는 것보다 훨씬 편할 때예요. 대부분은 쓸 일이 없어요.

## 브라우저나 먼 곳에서 실행하기

마지막 두 가지는 이 Mac 앞에 앉아 있지 않을 때도 매크로를 실행할 수 있게 해 주는 기능이에요.

- **Web Server**(웹 서버): 설정의 **Web Server** 탭에서 켜면 웹 브라우저로 이 Mac의 Keyboard Maestro에 접속할 수 있어요. 기본 주소는 `http://localhost:4490`이에요. 사용자 이름과 비밀번호를 설정해 두면 로그인한 뒤 활성 상태인 모든 매크로를 실행할 수 있어요. **Public Web**(공개 웹) 트리거를 단 매크로는 이 Mac에 접속할 수 있는 사람이라면 누구나 비밀번호 없이 실행할 수 있어요. 공식 위키에 따르면 대부분의 가정용 네트워크에서는 같은 로컬 네트워크에 있는 컴퓨터만 접속할 수 있지만, 네트워크 설정에 따라서는 인터넷의 누구나 접속할 수도 있다고 해요([공식 위키](https://wiki.keyboardmaestro.com/trigger/Web_Server)).
- **Remote**(원격) 트리거: 매크로에 Stairways Software 웹 서버를 거치는 URL을 하나 발급해 줘요. 인터넷이 되는 곳이라면 어디서든 이 URL을 열기만 하면 로그인 없이 매크로가 실행돼요. 공식 위키는 이 점을 분명하게 경고해요. URL을 아는 사람이라면 누구나 매크로를 실행할 수 있으니 아주 무해한 매크로에만 쓰라는 거예요. 또 이 기능은 앞으로도 계속 제공되거나 매번 작동한다는 보장이 없으니, 중요한 일에는 기대지 마세요([공식 위키](https://wiki.keyboardmaestro.com/trigger/Remote)).

<strong>실제로 필요할 때</strong>: 휴대폰이나 다른 컴퓨터에서 한 번 탭해서 이 Mac에 부담 없는 작은 일을 시키고 싶을 때예요. 둘 중 무엇을 켜든, 누가 접속할 수 있는지부터 먼저 생각해 보세요.

이것으로 전체 가이드가 모두 끝났어요. 나머지 내용은 순서대로 공부할 필요가 없어요. 구체적으로 해 보고 싶은 일이 생기면 [활용법](/ko/howto/)에서 찾아보고, 모르는 용어가 나오면 [위키](/ko/wiki/)를 확인해 보세요.

## 막혔나요?

<Q q="셸 스크립트가 터미널에서는 잘 되는데, Keyboard Maestro에 넣으면 명령어를 찾을 수 없대요.">
<p>Keyboard Maestro는 스크립트를 실행할 때 시스템에 기본으로 들어 있는 몇몇 폴더에서만 명령어를 찾고, 터미널 설정은 읽지 않아요. 명령어의 전체 경로를 적어 주거나, <code>ENV_PATH</code>라는 변수를 만들어 필요한 경로를 넣어 두세요.</p>
</Q>
<Q q="스크립트에서 Keyboard Maestro 변수를 읽지 못해요.">
<p>셸 스크립트에서는 <code>$KMVAR_</code> 뒤에 변수 이름을 붙이고, 이름의 공백은 밑줄로 바꿔야 해요. JXA에서는 <code>kmvar.</code> 뒤에 같은 식으로 밑줄을 써서 변수 이름을 적어요. 그런 다음 스크립트 옆 메뉴를 확인해 보세요. 변수를 하나도 넘기지 않도록 설정돼 있을 수 있어요. 참고로 비밀번호 변수는 원래 JXA에서 읽을 수 없어요.</p>
</Q>
<Q q="셸 스크립트 안에서 변수를 바꿨는데 매크로의 값은 그대로예요.">
<p>환경 변수는 읽기 전용 복사본이에요. 스크립트가 결과를 출력하게 만들고, 동작의 결과를 변수에 저장하도록 설정하세요. AppleScript와 JXA는 <code>setvariable</code>로 값을 직접 다시 쓸 수도 있어요.</p>
</Q>
<Q q="서브루틴의 매개변수를 바꿨더니 그걸 호출하는 매크로에서 오류가 나요.">
<p>매개변수는 순서대로 전달돼요. 서브루틴의 Subroutine 트리거를 열고 Callers 메뉴에서 호출하는 매크로마다 이동해 매개변수 순서를 다시 맞춰 주세요.</p>
</Q>
<Q q="두 번째 Mac에서 동기화를 시작했더니 원래 있던 매크로가 없어졌어요.">
<p>Open Existing을 클릭하면 두 번째 Mac의 기존 매크로가 동기화 파일의 매크로로 교체돼요. Keyboard Maestro가 이전 백업 버전을 보관해 두니 <strong>File ▸ Revert Macros</strong>(파일 ▸ 매크로 되돌리기)에서 필요한 백업이 있는지 확인해 보세요. 다음부터는 먼저 내보내기 한 뒤 동기화를 시작하세요.</p>
</Q>
<Q q="플러그인 동작을 설치했는데 동작 목록에 안 보여요.">
<p>설치한 뒤에는 편집기와 엔진을 모두 다시 시작해야 인식될 때가 있어요. 엔진을 종료한 다음 편집기도 닫았다가 다시 열고, Third Party Plug Ins 분류에서 찾아보세요.</p>
</Q>
