프리랜서의 다운로드 폴더는 아무도 치우지 않는 현관과 비슷해요. 클라이언트가 보낸 계약서와 청구서 PDF, 웹에서 저장한 이미지, 앱 설치 파일이 한꺼번에 뒤섞여 쌓이곤 하죠. 월말에 정산을 하려면 그 파일 더미 속에서 이번 달 PDF만 하나씩 찾아내야 해요. 이 페이지에서 만들 매크로가 그 현관을 대신 지켜 줄 거예요. PDF 파일은 다운로드가 끝나자마자 문서 폴더 안의 “PDF 수신함”이라는 폴더로 알아서 옮겨지고, 나머지 파일은 나중에 시간이 날 때 정리할 수 있도록 제자리에 그대로 남아요.

<mark>Folder 트리거가 문 앞을 지켜 줘요. 파일이 하나 들어올 때마다 그 파일의 경로를 손에 쥔 채 매크로가 한 번씩 실행돼요.</mark>

## Folder 트리거가 하는 일

앞선 페이지의 매크로들은 키를 누르거나 몇 글자를 입력해야 실행됐어요. 하지만 이번 매크로는 따로 조작하지 않아도 알아서 돌아가요. <Term k="触发器" text="트리거" />가 **Folder**(폴더)이기 때문이에요. 폴더를 하나 지정해 두면, 그 안에 항목이 추가되거나 삭제될 때, 또는 둘 중 어느 쪽이든 변화가 생길 때마다 매크로가 한 번씩 실행돼요([Folder trigger](https://wiki.keyboardmaestro.com/trigger/Folder) 참고). 매크로가 실행되면 `%TriggerValue%` <Term k="令牌" text="토큰" />에 방금 들어온 파일의 전체 경로가 담기고, 뒤에 이어지는 동작들이 이 경로를 보고 어떻게 처리할지, 어디로 옮길지 결정해요.

여기서 아주 중요한 옵션이 하나 있어요. 바로 **ignore partial or changing files**(미완성 또는 변경 중인 파일 무시)예요. 다운로드는 시간이 걸리기 때문에 파일이 폴더에 막 나타났을 때는 아직 내려받기가 끝나지 않은 상태예요. 이 옵션에 체크해 두면 트리거가 파일 변경이 멈출 때까지 기다렸다가 매크로를 실행하고, 아직 다운로드 중임을 뜻하는 확장자가 붙은 임시 파일도 무시해요.

## 매크로 만들기

먼저 Finder에서 파일을 옮길 대상 폴더부터 준비하세요. 문서 폴더 안에 “PDF 수신함”이라는 새 폴더를 만들면 돼요. 공식 문서에 따르면 **Move**(이동)은 이미 존재하는 폴더를 대상으로 지정해야 하므로, 이 단계를 건너뛰면 안 돼요.

그런 다음 항상 활성 상태인 매크로 그룹 안에 “PDF 자동 정리”라는 이름으로 새 매크로를 만드세요.

**트리거.** **Folder** 트리거를 추가하고, 폴더는 다운로드 폴더로 고른 뒤 조건을 **adds an item**(항목이 추가될 때)로 맞추고 **ignore partial or changing files**에 체크하세요.

**PDF인가요?** **If Then Else**(조건 분기) 동작을 추가하고 조건으로 **Text**(텍스트)를 고르세요. 확인할 텍스트 칸에는 `%TriggerValue%`를 넣고, 비교 방식은 **ends with**(~로 끝남)을 선택한 뒤 `.pdf`를 입력하세요. 공식 문서에 따르면 이 비교는 대소문자를 구분하지 않기 때문에 `.PDF`로 끝나는 파일 이름도 똑같이 해당해요([Text condition](https://wiki.keyboardmaestro.com/condition/Text) 참고).

**파일 옮기기.** If Then Else의 “then”(조건이 맞을 때) 칸에 **File Actions**(파일 동작)을 추가하고 **Move**를 고르세요. 옮길 파일에는 `%TriggerValue%`를 넣고, 대상 폴더에는 아래 경로를 입력하세요.

<Copy id="wf-dest" title="대상 폴더" code="~/Documents/PDF 수신함" />

`~`는 홈 폴더를 뜻해요(Finder에서 보이는 “문서” 폴더는 실제 경로에서는 Documents로 적어요). “else”(아니면) 칸은 비워 두세요. 그래야 PDF가 아닌 파일은 건드리지 않고 그대로 두거든요.

이미지 파일도 함께 분류하고 싶다면 **If Then Else** 동작을 하나 더 추가하고 조건을 **any of the following are true:**(다음 중 하나라도 참일 때)로 바꾸세요. 그 안에 **Text** 조건을 세 개 넣어 이름이 `.png`, `.jpg`, `.jpeg`로 끝나는지 확인한 뒤, 사진 폴더 안에 미리 만들어 둔 폴더로 옮기면 돼요.

## 잘 작동하는지 확인하기

Safari에서 PDF 파일을 다운로드 폴더에 저장하거나, 이메일 첨부 파일을 다운로드 폴더에 저장해 보세요. 다운로드가 끝나고 몇 초쯤 기다리면 다운로드 폴더에서 파일이 사라지고 “PDF 수신함”에 나타날 거예요. 비교해 볼 겸 이미지 파일도 하나 저장해 보세요. 이미지는 다운로드 폴더에 그대로 남아 있어야 해요.

참고로 이 매크로는 지금부터 새로 들어오는 파일만 처리해요. 매크로를 만들기 전부터 다운로드 폴더에 이미 들어 있던 PDF들은 트리거가 건드리지 않아요. 기존 파일들은 한 번만 손으로 옮기거나, [여러 파일 이름 한꺼번에 바꾸기](/ko/howto/rename-files/)에 나오는 For Each 방법으로 한꺼번에 처리할 수 있어요.

## 막혔나요?

<Q q="다운로드가 끝났는데 파일이 옮겨지지 않아요.">
먼저 매크로와 매크로 그룹에 모두 체크 표시가 되어 있는지, 엔진이 실행 중인지, 트리거가 정말 다운로드 폴더를 가리키고 있는지 확인해 보세요. 그다음에는 압축이 풀린 파일처럼 다운로드 폴더 안의 하위 폴더에 파일이 들어간 건 아닌지 살펴보세요. 공식 문서에 따르면 트리거는 이 폴더 바로 안에 놓인 항목만 감지하고, 하위 폴더 안의 변화는 감지하지 않아요.
</Q>
<Q q="파일이 옮겨지기까지 몇 초나 걸려요.">
정상이에요. 공식 문서에 따르면 파일 변경이 멈췄는지를 Keyboard Maestro가 미리 알 수 없기 때문에, 변경이 끝나기를 기다리는 과정에서 어쩔 수 없이 약간의 지연이 생겨요. 이 몇 초 덕분에 덜 내려받은 파일이 중간에 옮겨지는 일을 막을 수 있어요.
</Q>
<Q q="매크로에서 오류가 나고 파일이 여전히 다운로드 폴더에 남아 있어요.">
“PDF 수신함”에 같은 이름의 파일이 이미 들어 있을 가능성이 커요. 공식 문서에 따르면 대상 폴더에 같은 이름의 파일이 이미 있으면 파일 이동이 실패해요. 기존 파일의 이름을 바꾸거나 다른 곳으로 옮긴 뒤, 이번 파일은 직접 옮겨 넣어 주세요.
</Q>
<Q q="파일이 옮겨진 뒤에 매크로가 한 번 더 실행된 것 같아요.">
트리거가 항목이 추가되거나 삭제될 때 모두 실행되도록 설정되어 있는지 확인해 보세요. 파일이 다른 곳으로 옮겨지면 다운로드 폴더 입장에서는 항목이 하나 줄어든 셈이라 매크로가 다시 실행돼요. **adds an item**만 선택해 두세요.
</Q>

<u>이런 매크로에는 삭제 동작을 넣지 마세요.</u> 보고 있지 않은 사이에도 새 파일이 들어올 때마다 자동으로 실행되거든요. 잘못 옮긴 파일은 다시 가져오면 되지만, 삭제한 파일은 되돌릴 수 없어요. 공식 문서에서도 **File Actions**의 삭제 옵션은 확인 창도 띄우지 않고 휴지통도 거치지 않는다고 따로 경고하고 있으니 각별히 조심해야 해요.

문 앞을 지켜 주는 매크로가 생기면 다운로드 폴더가 더 이상 산더미처럼 쌓이지 않아요. 매일 정해진 시간이나 특정 Wi-Fi 네트워크에 연결될 때처럼 다른 순간에 알아서 실행되는 매크로가 궁금하다면 [매일 같은 시간에 실행하기](/ko/howto/daily-schedule/)와 [전체 가이드 2단계](/ko/guide/2-triggers/)를 살펴보세요.
